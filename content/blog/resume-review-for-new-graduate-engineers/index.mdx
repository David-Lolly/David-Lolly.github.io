# 帮老同学修改简历的一次复盘

前段时间，一个朋友突然找到我，说我们高中有个同学也是学计算机的，现在正在找实习，想请教一些求职相关的问题，问我是否方便把微信推给他。

我抱着看看能不能帮到他的想法答应了。

第二天，这位老同学联系了我。我们高三时期是室友，但其实关系并没有特别深。他一开始还是比较客气，聊了一些生活上的事情，我也能够感受到他的不好意思和拘谨。所以我直接告诉他：有什么需要帮忙的直接说，不用客套。

后来他说明了来意，希望我帮他看看简历。他走的是 Java 开发方向。从目前的就业环境来看，Java 开发岗位竞争已经非常激烈，尤其对于普通院校背景的应届生来说，求职压力更大。

同时，随着 AI Coding 的快速发展，软件开发行业正在发生变化。过去企业招聘初级开发，可能更加关注掌握多少框架、写过多少代码，但现在仅仅会完成基础业务开发，已经很难形成明显竞争力。

企业越来越关注的是：一个工程师是否具备解决问题的能力，是否能够快速学习新技术，以及是否能够利用 AI 等工具提升自己的开发效率。

看完他的简历后，我发现了一些比较典型的问题。

---

## 简历结构需要符合应届生特点

第一个问题是联系方式。

他的简历顶部没有放微信。现在国内招聘场景中，微信已经成为非常重要的沟通方式，所以简历中的联系方式建议优先放微信，其次是电话和邮箱。这虽然是一个很小的细节，但实际上会影响招聘者后续联系你的效率。

第二个问题是简历结构。

他的简历把专业技能放在最前面，而教育经历放在了最后。对于已经工作的开发者来说，这种结构没有问题，因为企业更加关注工作经历和项目成果。但是对于应届生来说，教育背景依然是企业判断候选人的重要依据。尤其是刚毕业的学生，学校、专业、项目经历和技术能力共同构成了企业对你的第一印象。

他可能考虑到自己的学校背景普通，所以想弱化教育经历，把技术能力放在前面。但实际上，这种做法意义并不大。学校背景是什么就是事实，没有必要刻意隐藏。更重要的是，简历应该按照招聘者理解信息的顺序展开。

我的建议是：教育背景放前面，然后是项目经历，最后再放专业技能。原因很简单。

单独罗列一堆技能，例如：

“熟悉 Spring Boot”
“熟悉 Redis”
“熟悉 MySQL”

其实并不能证明什么。招聘者真正关心的是：你在哪里使用过这些技术？为什么这么设计？解决了什么问题？

所以，技能应该依托项目体现，而不是孤立展示。

---

## 不要害怕展示 AI Coding 能力

他的简历中还有一个比较明显的问题，就是完全没有体现 AI Coding 能力。

我能够理解学生为什么会这么做。很多人在学校阶段会形成一种观念：如果使用 AI 写代码，是不是代表自己的能力不够？甚至会觉得这和考试作弊类似。必须完全依靠自己，从零开始写代码，才能证明自己真正具备能力。但进入工作之后，你会发现现实完全不是这样。工作中，没有人关心你的代码是不是一行一行手写出来的。企业真正关心的是：
你能不能把事情做好。

如果你能够利用 AI：

* 快速分析需求；
* 拆解功能模块；
* 辅助技术方案设计；
* 编写和优化代码；
* 生成测试用例；
* 辅助定位问题；

同时你能够理解整个过程，并且对结果负责，那么这反而体现了你的工程能力。工程师的价值，从来不是单纯写代码。过去我自己也有类似误区，总觉得所有事情都必须自己完成，不能依赖外部工具，否则无法证明自己的能力。但工作之后才发现，真正优秀的工程师并不是不用工具的人，而是能够驾驭工具的人。工具本身没有价值，如何使用工具解决问题才有价值。搜索引擎、技术文档、开源项目、同事经验、AI 工具，本质上都是工程师解决问题的手段。在现在这个时代，一个完全拒绝 AI Coding 的工程师，反而可能会被认为缺乏对新技术的接受能力。

从我身边来看，目前几乎没有工程师手搓代码。


---

## 项目经历需要展示真实能力

他的个人项目描述也比较简单。我的建议是，把项目代码公开到 GitHub。

原因很简单：

> Talk is cheap, show me the code.

简历里的项目描述，本质上只是自己的介绍，而代码仓库能够直接证明项目真实性。同时，一个维护良好的 GitHub 项目，也能够体现很多工程基础能力：

* Git 使用能力；
* 代码管理习惯；
* README 编写能力；
* 项目维护意识。

这些都是软件工程师非常基础的能力。除此之外，现在项目描述也不能只是简单写：

“完成了某某系统”
“实现了某某功能”

而应该体现完整的工程过程。

例如：

需求阶段，如何分析需求；

设计阶段，为什么选择这个技术方案；

开发阶段，如何使用 AI 辅助开发；

测试阶段，如何验证功能正确。

企业真正想看到的是：你是否具备利用现代工具完成工程任务的能力。而不是简单证明：会不会写代码。

---

## 写在最后

这次帮老同学修改简历，让我重新思考了一下现在应届生程序员求职的问题。过去的软件开发竞争，更多是在比较：谁掌握的技术更多，谁写的代码更多。但是未来的软件开发竞争，很可能变成：谁能够更快、更好地利用各种工具，把想法变成可靠的软件。对于准备进入软件行业的学生来说，不要把 AI 当成作弊工具。

真正需要培养的是：理解问题的能力、设计方案的能力、判断结果的能力，以及驾驭工具的能力。AI 不会简单替代工程师。但不会使用 AI 的工程师，很可能会逐渐失去竞争优势。

希望这次简历修改的复盘，能够帮助正在寻找实习和工作的同学。
